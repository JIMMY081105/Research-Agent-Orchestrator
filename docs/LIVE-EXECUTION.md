# Live execution integration

This candidate connects the approved Flask / Jinja2 / HTMX desktop layout to the
existing subscription-backed native Codex worker. It is separate from scientific
generation code and does not start Factory80's unapproved batch.

The host submits a durable task with a unique ID and native session. Codex runs
with the selected native permission profile; a fresh tool-disabled Claude reviews
the bounded evidence. Concrete REWORK findings return to the same owned task,
at most twice. Each attempt and review is retained. Network, login, quota and
uncertain process failures pause rather than replaying work or changing billing.

Task review packets have a 24,576-byte ceiling. Oversized evidence is rejected
before charging a model call. Full manifests and transcripts stay local. The
review includes complete differences and necessary unchanged local source; it
does not repeatedly read the entire research history. Provider-reported input,
output and cache counters are recorded without estimates or double counting.

The real UI provides Prompt submission, visible execution records, explicit
permission decisions and a Progress page. Unavailable services disable Send.
Only connected model IDs are offered. Task/Standard are the connected workflow
and speed controls; unimplemented modes are not represented as enabled features.
Text analysis uses the native read-only sandbox. The compact GPU chip remains
explicit demonstration data; it does not certify server activity.

Worker installation requires current tests and an independent fixed-source review.
Its Windows task uses a frozen snapshot, the current user, no saved password,
no wake and duplicate suppression. The previous desktop/core/VPN/archive tasks
are not replaced. Existing worker records and review charges remain intact.
