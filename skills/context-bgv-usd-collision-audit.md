# USD 建筑碰撞诊断

从“看得见的几何”和“实际参与物理的几何”之间定位差异。默认先检查并报告；只有本次已授权的目录与对象才能修改，不因为技能内容自动编辑研究源资产。

## 检查顺序

1. 读取资产及依赖清单、metersPerUnit、upAxis、层变换和实例关系，在统一世界坐标下比较。
2. 按当前资产的 guide/default/render 与语义规则枚举应有对象，形成覆盖率分母；逐对象核对 mesh、CollisionAPI、启用状态及用途。不能只比较两层计数是否对称，也不能把一个聚合 collider 当所有物体覆盖。
3. 对静态建筑构件，沿祖先检查 RigidBodyAPI 和 collision approximation。动态刚体祖先可能把楼梯三角网格凸化成斜坡；可动设备/门另有语义，不能全局删除刚体 API。
4. 检查门洞的墙体 visual/guide collider 与门扇、把手、门框，区分建筑门和家电门。避免一刀切关闭所有碰撞体。先定位遮挡来源，再提出最小修复。
5. 对已授权导出的候选，保存后重开，读取真实顶点、三角形、变换及物理属性；不能用导出函数的返回值代替回读。
6. 如果获准运行物理后端，用同一资产、坐标和明确设备执行约定的 query/contact/sweep。USD 上有 collider 或点在 AABB 内，不说明 PhysX 已注册它。

## 判读

- 空网格、非有限数、退化面、未加载依赖、错误变换分别报告；watertight 要按对象的碰撞表示合同判定，薄片/曲面不能套用封闭体规则。
- 可见渲染、碰撞灰模、碰撞结构检查和真实接触是不同层级。
- 静态几何改动后，相关 scratch、manifest、图、探针与验收按依赖失效，保留原失败记录。
- 没有授权或可用的真实运行时，就明确停在几何诊断层，不把 CPU 检查写成仿真成功。

交付对象级证据：应有/已启用、世界坐标范围、祖先物理语义、实际查询结果、定位到的阻挡体及修复影响。复用 [常见反例](references/cases.md) 时重新核对当前资产。
