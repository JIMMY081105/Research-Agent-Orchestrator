# 建筑研究的证据与验收

将“文件生成了”“程序运行了”“某门通过了”和“研究任务完成了”分别判断。这份技能不增加研究写入、GPU、旧任务恢复或发布权限；遵守本次用户授权与实际工具限制。

## 开始时固定验收对象

- 找到本次任务的目标、输入资产、源码、配置、依赖、种子、输出目录和验收合同。缺失项标为 UNKNOWN；读取已有 handoff、失败及停机记录。
- 绑定实际文件内容与相关依赖，而非只记录 HEAD。工作区未提交变化、外部工具、选用 skill 与配置模板都可能影响结果。
- 先保留原有记录。新的小任务或新的技能安装不恢复旧批次、不重置其返工/调用记录，也不解除旧任务的停机条件。

## 按证据层级判断

1. 结构：文件可解析、单位/坐标正确、对象完整。
2. 几何与碰撞：真实网格、启用的 collider、空间尺寸和通行约束。
3. 原生运行时：实际加载目标资产，执行物理查询或约定的最小动作。
4. 行为：固定策略、场景与种子下的真实机器人评估，记录成功/失败及分母。
5. 批次：当前合同要求的全部场景、门禁、图像或人工门均有对应证据。

只声明已证实的层级。渲染、G25 连通或张量合法不单独证明 humanoid 能通过；单栋/单门 PASS 不推出整批 READY。

## 让验收能够失败

- 选择一个有效正例和一个只改变目标条件的负例。事先写明预期被哪个判据、以何种原因拒绝。
- 负例因语法错误、缺依赖、认证失败、OOM 或接口异常退出，不算科学负对照成功。
- 几何、输入或执行闭包改变时，失效的是受影响的验收链；重建对应 scratch/manifest，不继承旧 PASS，也不改写历史。
- 对分块、并行、缓存等优化，按合同比较原生与新路径的数组、dtype、shape、顺序和逐位结果；加入改变真实输入的反例。样品等价只支持该样品范围。
- 若关键负对照失效，执行当前任务合同规定的停止/降级；仅处理本系统明确拥有且获准处理的进程，不停止旁边的研究工作。

## 交付

给出每项判据的 PASS / FAIL / NOT EXECUTED / UNVERIFIED、输入/源码/产物身份、正负对照证据、失败原因和剩余范围。UNKNOWN 不改写为 FAIL。总体结论按当前合同计算，不用“多数通过”覆盖硬失败；没有新实测时明确是历史证据复核。

读取 [历史反例](references/cases.md) 可帮助识别容易误判的结果。
