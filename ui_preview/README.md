# Scene Control workspace

There is one daily application: **BGV Scene Control** on Desktop or Start, with the window title **Scene Control**. The existing taskbar entry opens the same application. The extra **Scene Control UI Preview** desktop shortcut is preserved in the owned runtime backup and removed from the desktop by `Consolidate`.

Flask + Jinja2 + locally pinned HTMX and small native JavaScript render the approved cyberpunk chat layout inside Windows WebView2. Prompt has the bottom composer and compact GPU chip; Progress has the stage view. Model/effort/permission menus open upward. GPU values in this new layout remain marked DEMO.

## Open

```powershell
& 'E:\Github\Research-Agent-Orchestrator\tools\approved-ui.ps1' -Mode Open
```

Both historical `Start-Preview.ps1` and `Start-Preview.ps1 -Desktop` now launch the same executable/profile/mutex. Reopening focuses the existing window and preserves its unsent draft. There is no second native preview application launched by these entry points.

The configured-machine startup helper checks the loopback UI owner at 127.0.0.1:8877 and starts its presentation server when absent. It refuses an unknown occupied port. It uses a project virtual environment and existing pinned WebView2 files. It does not install or restart a worker, research task, VPN or Windows scheduled task.

## Entry maintenance

```powershell
& 'E:\Github\Research-Agent-Orchestrator\tools\approved-ui.ps1' -Mode Status
& 'E:\Github\Research-Agent-Orchestrator\tools\approved-ui.ps1' -Mode Consolidate
```

Consolidate validates the three owned canonical shortcuts, prepares the one native binary and retires only the exact owned extra desktop preview shortcut, recording its byte hash and backup. It leaves the existing installation/restore receipts intact. `Restore` explicitly restores the older accepted dashboard shortcuts from those original receipts; it is not the normal way to open this layout.

## Execution status

The execution integration is a **candidate, not an accepted worker deployment**. A missing verified worker is shown as WORKER OFFLINE / 执行服务未就绪 and leaves Send disabled. This is the same application with its execution service unavailable, not a second product. A UI-only entry repair does not make the backend DEPLOYED.

With an independently accepted installed worker, the candidate submits explicit Codex Task/Standard turns or fresh read-only text analysis, shows actual browser-owned progress/approvals and independent Claude review with at most two repairs. Model choices come from the actual CLI. Plan/Goal/Fast remain unaccepted execution modes. Full Access removes native OS confinement/approvals for that turn but grants no new research, GPU or publication authorization.

UI polling invokes no model calls. Source and private runtime remain separate. Frontend layout/entry changes do not require Claude review under the user's instruction. See [execution integration](../EXECUTION-INTEGRATION.md) for remaining deployment gates.

For a new configured checkout, create a project virtual environment from `ui_preview/requirements.txt`; this is not a portable installer. `python -B ui_preview/app.py` runs the loopback renderer. Templates live in `ui_preview/templates`, styling in `ui_preview/static/style.css`; HTMX is vendored with license/provenance. No React or build pipeline is required.
